## Избавиться от RCON в пути робота

Сейчас адаптер в демо подключает карту-оракул `stand.adapter_map:oracle`: RCON `save-all flush`, region-файлы
сервера и `testforblock`. Это знание всего мира в реальном времени, у настоящего робота его нет. Ещё из-за него
агент не стартует без сервера: `oracle()` подключается к RCON при запуске адаптера.

- Нужна разведанная карта: клетки из `geo_scan`, `surroundings`, результатов `move` и `place` робота.
  Неизвестное считается свободным, на `BLOCKED` клетка помечается занятой, путь перестраивается
  (`move_to` уже умеет перестраивать путь после `ad.map.invalidate()`). Сохранять карту между запусками по `world_id`.
- Мешает интерфейс карты: `WorldMap` синхронный и не может вызывать робота. Нужен доступ карты к вызовам
  робота или асинхронный интерфейс.
- `verify_blocks` честно может проверить только «есть блок или нет» (твёрдость из `geo_scan`).
  Точное имя блока робот видит только вплотную.
- RCON остаётся у стенда: сброс, судья и fake-MCP. Это знание проверяющего, а не робота.
- Пока оракул в демо оставлен. Его RCON подключается лениво (`stand/adapter_map.py`): агент стартует без сервера,
  а `move_to`, `place_at` и `verify_blocks` отвечают `UNKNOWN` с подсказкой `uv run oc up`. Правильный код
  (`CONNECTION_LOST` или отдельный) выбирает адаптер, это к слиянию адаптера с MCP.

## Подключить Java-pathfinding коллеги (`pathfinding/java/`)

Что он умеет: 2D A\* по `HeightMap` чанков из `<мир>/region/*.mca` с полётом на 3 блока над поверхностью,
сначала маршрут по регионам 512×512, затем внутри региона. На выходе относительные команды (`forward N`, повороты).

- Он для дальних переходов, не для стройки: не видит свежих блоков (сейв обновляется только при сохранении мира),
  пещер и навесов. Он тоже читает сейв, то есть тоже «знание мира» и тоже требует доступа к сейву.
- Варианты: подсказка маршрута для `move_to` на большие расстояния (если сейв доступен), а последние метры
  и стройка по разведанной карте. Или отказаться в пользу точек маршрута из memory.
- Технически: Java 17 и Maven, зависимости через jitpack. Сервер стенда на Java 8. Нужен способ вызова
  (CLI-процесс или порт на Python) и формат «путь клетками» вместо команд.
- Убрать дубли A\*: `adapter/pathfinding.py`, `stand/fake_mcp/pathfinding.py`, `pathfinding/prototype-py/`.

## Слить адаптер с MCP (`adapter/` и `bridge/`)

Делает коллега, автор MCP. Сейчас цепочка такая: агент → адаптер → (MCP по stdio, дочерний процесс) → мост → HTTP → Lua.

- Lua отдаёт `ok, text, data` с кодом ошибки, слоты как `name:damage`. Тогда уходят регулярки
  `adapter/codes.py` и `adapter/parse.py` и копии текстов в `stand/fake_mcp/texts.py`.
- Ошибки tools как результат с `isError: true`, а не JSON-RPC error.
- Один долгоживущий процесс: HTTP для робота, раздача Lua (сейчас `demo/lua_server.py`), MCP по HTTP.
  Робот перестанет терять связь при перезапуске агента, снимется ограничение «один клиент на порт 8765».
  Стенд уже умеет `real.url`.
- После слияния: fake-MCP стенда собрать как адаптер плюс симулятор робота вместо `stand/fake_mcp/additions.py`
  и теста паритета. Один реестр tools вместо шести мест (мост, Lua, адаптер, fake-MCP, два документа контракта, валидатор).

## Подключить memory (`memory/`)

memory хранит редкие POI (`chest`, `machine`, `base`, `waypoint`, `hazard`...), предпочтения и эпизоды-уроки
и говорит только с агентом. Разведанную карту он не заменяет: сетку клеток должен вести адаптер автоматически.

- Подключить агенту в демо (`.mcp.json` из `demo/agent_workspace.py`), отдельная база на `world_id`.
  На стенде с пустой базой на прогон (`MEMORY_DB` в рабочей папке), иначе ломается повторяемость.
- В скиллах: `brief` в начале задачи (склад, машины, база) вместо `oc-harness.yaml` и повторных поисков,
  `remember_poi` после находок, `remember_episode` в конце.
- Для поиска пути: `hazard` как запретные зоны, `waypoint` как точки дальнего маршрута.
- Договориться о формате id: memory требует `^[a-z][a-z0-9_]*:...`, а NEI отдаёт `mod:name:damage`
  (`minecraft:iron_ingot:0`, `IC2:blockMachine:3`).
- Документация memory ссылается на `nei.resolve` и `nei-mcp`, которых нет. Есть `nei_find`.
