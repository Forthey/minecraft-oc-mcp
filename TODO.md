## Избавиться от RCON в пути робота

Сейчас адаптер в демо подключает карту-оракул `stand.adapter_map:oracle`. Она смотрит на мир через RCON
(`save-all flush`, затем чтение region-файлов сервера и `testforblock`) и знает весь регион в реальном времени.
У настоящего робота такого знания нет.

- Нужна разведанная карта, которую робот строит сам: клетки из `geo_scan`, `surroundings` и результатов `move`
  и `place`. Неизвестная клетка считается свободной; если робот упёрся (`BLOCKED`), клетка помечается занятой,
  и путь перестраивается. `move_to` уже умеет перестраивать путь после `ad.map.invalidate()`. Карту сохранять
  между запусками по `world_id`.
- Мешает интерфейс карты: `WorldMap` синхронный и не может сам вызывать робота. Нужно дать карте доступ к вызовам
  робота или сделать интерфейс асинхронным.
- `verify_blocks` по-честному может проверить только, есть в клетке блок или нет (по твёрдости из `geo_scan`).
  Точное имя блока робот узнаёт, только подъехав вплотную.
- У стенда RCON остаётся: сброс площадки, судья и fake-MCP. Это знание проверяющего, а не робота.
- Пока оракул в демо оставлен. Его RCON подключается при первом обращении (`stand/adapter_map.py`), поэтому агент
  стартует и без сервера, а `move_to`, `place_at` и `verify_blocks` отвечают `UNKNOWN` с подсказкой `uv run oc up`.
  Правильный код ошибки (`CONNECTION_LOST` или отдельный) выбирает адаптер, это задача для слияния адаптера с MCP.

## Подключить Java-pathfinding коллеги (`pathfinding/java/`)

Что он умеет: двумерный A\* по `HeightMap` чанков из `<мир>/region/*.mca`, робот летит на 3 блока над поверхностью.
Сначала строится маршрут по регионам 512 на 512 блоков, затем путь внутри региона. На выходе относительные команды
(`forward N` и повороты).

- Он подходит для дальних переходов, но не для стройки. Свежих блоков он не видит (сейв обновляется только
  при сохранении мира), пещер и навесов тоже. И он сам читает сейв, то есть это то же знание всего мира,
  и ему нужен доступ к сейву.
- Варианты: подсказка маршрута для `move_to` на большие расстояния (если сейв доступен), а последние метры
  и стройка по разведанной карте. Или отказаться от него в пользу точек маршрута из memory.
- Технически: Java 17 и Maven, зависимости через jitpack, а сервер стенда работает на Java 8. Нужен способ вызова
  (отдельный процесс или порт на Python) и ответ в виде пути по клеткам, а не команд.
- 3D A\* в Python один: `adapter/pathfinding.py`, fake-MCP стенда импортирует его. `pathfinding/prototype-py/` это
  прототип того же планировщика по карте высот, что и Java-версия. Когда решим судьбу Java-версии, прототип удалить.

## Слить адаптер с MCP (`adapter/` и `bridge/`)

Это делает коллега, автор MCP. Сейчас цепочка такая: агент, адаптер, затем MCP по stdio к дочернему процессу
моста, мост, HTTP, Lua на роботе.

- Lua отдаёт `ok, text, data` с кодом ошибки, слоты в виде `name:damage`. Тогда не нужны регулярки
  в `adapter/codes.py` и `adapter/parse.py` и копии текстов в `stand/fake_mcp/texts.py`.
- Ошибки tools возвращаются результатом с `isError: true`, а не ошибкой JSON-RPC.
- Один долгоживущий процесс: HTTP для робота, раздача Lua (сейчас это `demo/lua_server.py`) и MCP по HTTP.
  Робот перестанет терять связь при перезапуске агента, к роботу смогут подключаться несколько клиентов
  (сейчас порт 8765 держит один). Стенд уже умеет подключаться по `real.url`.
- После слияния: собрать fake-MCP стенда из адаптера и симулятора робота вместо `stand/fake_mcp/additions.py`
  и теста паритета. Свести список tools в один реестр вместо шести мест: мост, Lua, адаптер, fake-MCP,
  два документа контракта и валидатор скиллов.

## Подключить memory (`memory/`)

memory хранит редкие подписанные точки (POI: `chest`, `machine`, `base`, `waypoint`, `hazard` и другие),
предпочтения игрока и эпизоды-уроки и общается только с агентом. Разведанную карту он не заменяет: сетку клеток
должен вести адаптер автоматически.

- Подключить агентам в демо: добавить сервер `memory` в `demo/agent_workspace.py` для всех трёх агентов
  (`.mcp.json`, `opencode.json` и флаги `-c` для Codex), отдельная база на `world_id`. На стенде нужна пустая
  база на каждый прогон (`MEMORY_DB` в рабочей папке), иначе прогоны перестанут быть повторяемыми.
- В скиллах: `brief` в начале задачи (склад, машины, база) вместо `oc-harness.yaml` и повторных поисков,
  `remember_poi` после находок, `remember_episode` в конце.
- Для поиска пути: `hazard` как запретные зоны, `waypoint` как точки дальнего маршрута.
- Договориться о формате id предметов: memory требует `^[a-z][a-z0-9_]*:...`, а NEI отдаёт `mod:name:damage`
  (`minecraft:iron_ingot:0`, `IC2:blockMachine:3`).
- Документация memory ссылается на `nei.resolve` и `nei-mcp`, которых нет. Есть `nei_find`.
